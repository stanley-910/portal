# China Railway 12306 — API ground truth
Checked: 2026-10-02 · Modes: trains · Seat: Ahmet

## Verdict
- **No official public API.** 12306 says it is the "唯一官方渠道" and "从未授权任何第三方平台" to sell tickets or do ticket business. No developer portal, no keys, no docs. [S1][S2]
- What exists = **unofficial internal web endpoints** (`station_name.js`, `leftTicket/query*`). Undocumented, path rotates, cookie-gated, risk-controlled (风控). Not "free API" — reverse-engineered scraping. [O1][O2][S3]
- **ToS/legal risk:** regulators (网信办 + 国家铁路局) ordered 7 big OTAs to stop using automated programs to hit 12306 at high frequency; 12306 risk control blocks/queues abnormal traffic. A hackathon app scraping it = bad idea. [S3][S4]
- Live seat query from US/EU Vercel: no-cookie call → HTTP 302 to error page (observed). Making it work needs session cookie dance; likely CAPTCHA/slider when flagged. Geo-blocking of foreign IPs `unverified`.
- **Use instead:** static seed timetable (our own JSON for few demo pairs) + affiliate deep links (Trip.com / 12Go) for price+booking. Only `station_name.js` is a low-risk, one-time, static fetch for station codes.
- Biggest blocker: no legit data source for live China train seats/prices at all.

## Auth + base URL
- None official. Observed host: `https://kyfw.12306.cn/otn/` (web app). [O1]
- Query endpoint name is read at runtime from `leftTicket/init` page JS: `CLeftTicketUrl = 'leftTicket/queryG'` today (historically `queryZ`, `queryA`, `queryO`… rotates — `unverified` history). [O2]
- Needs browser-like session cookies set by `leftTicket/init` + others; exact cookie set `unverified`.

## Endpoints we use
Recommendation: **use only row 1, once, at build time.** Rows 2 are documented for awareness, not for implementation.

| Method + path | Purpose | Key params | Key response fields |
|---|---|---|---|
| GET `/otn/resources/js/framework/station_name.js` | station list (static JS) | — | `var station_names='@bjb\|北京北\|VAP\|beijingbei\|bjb\|0\|0357\|北京\|\|\|@…'` — fields: short pinyin, 中文名, **telecode** (e.g. `BJP`), full pinyin, initials, index, city code, city name [O1] |
| GET `/otn/leftTicket/queryG` (name rotates) | left tickets A→B | `leftTicketDTO.train_date=YYYY-MM-DD` `leftTicketDTO.from_station=BJP` `leftTicketDTO.to_station=SHH` `purpose_codes=ADULT` | community-known: `data.result[]` pipe-delimited strings + `data.map` code→name `unverified`; without cookies → 302 [O2] |

## Limits
- None published. Risk control throttles/blocks "high-frequency" patterns; 12306 refused 1.056M tickets from 抢票软件 in one holiday window (press). [S3][S4]
- `station_name.js` static: fetch once, commit to repo, refresh manually.

## Coverage
- 12306 itself: all China Railway (CR) trains, live seats, fares, booking (for account holders).
- Via us legally: **station codes only** (static) + hand-off links. No live seats/fares.
- Static research data [S8]: ~727 stations, 3,399 HSR trains, Oct 2019–Jan 2020 — stale.

## Errors
- No documented error contract. Observed: missing session → 302 to `/mormhweb/logFiles/error.html` [O2]. Flagged traffic → CAPTCHA/slider or empty results `unverified`.

## Gotchas
- Query path name is not stable — scraped integrations break silently.
- Response is pipe-delimited positional strings; index meaning undocumented → silent field shifts.
- Running from Vercel US/EU: added latency, unknown blocking; can't promise demo-day uptime.
- GitHub libs (`py12306`, etc.) are scrapers — same ToS/legal problem, don't vendor.
- `station_name.js` telecodes (`BJP`, `SHH`) ≠ IATA, ≠ Trip.com/12Go slugs; keep mapping table.
- 12306 English site exists (`https://www.12306.cn/en/index.html`, HTTP 200) — for user hand-off link only. [O3]
- Do not show "live" seat data we don't have; label seed timetables "indicative".
